# Set up Moonbase Books on Jellyfin

This is an administrator guide. End users install a [Moonfin Books client](https://github.com/ZepiGit/Moonfin-Books/blob/main/docs/INSTALL.md) or open the web app served by this plugin. The released **Moonbase Books 2.3.1.100** ZIP was deployed and checked with **[Jellyfin 12.1](https://github.com/jellyfin/jellyfin/releases/tag/v12.1)** and **[Shelfmark Lite 1.3.15](https://github.com/calibrain/shelfmark/releases/tag/v1.3.15)**. Other version combinations need independent checks; this is not a general compatibility promise.

## 1. Prepare the dependencies

1. Install and configure [Jellyfin Server](https://jellyfin.org/downloads/server/) using its [official installation guide](https://jellyfin.org/docs/general/installation/). Create the book and/or audiobook libraries you intend users to browse. Determine the **actual** Jellyfin configuration and plugins paths for your native or Docker installation from that guide; the examples below are not universal paths.
2. Install [Shelfmark](https://github.com/calibrain/shelfmark) on a network reachable **from Jellyfin**. Configure its metadata/search provider and its [Prowlarr](https://wiki.servarr.com/prowlarr/installation) adapter with indexers you are permitted to use. This Books bridge accepts only Shelfmark's `prowlarr` release source.
3. Configure a download client supported by those results, such as [SABnzbd](https://github.com/sabnzbd/sabnzbd) for Usenet. In Shelfmark and the downloader, set matching book/audiobook categories and the completed-download location. Verify that Shelfmark sees completed files at the path it is configured to read. Configure a persistent final import destination that Shelfmark can write and Jellyfin libraries can read. With containers, check network names, mounts, permissions, and **paths as seen inside each container**; a host path is not automatically a valid container path. [Docker Engine installation](https://docs.docker.com/engine/install/) is optional if you use native services.
4. Keep provider, indexer, and downloader credentials in protected service configuration. The plugin does not install or configure these services. The separate `books-auth` website, Audiobookshelf, and post-import automation used by some operators are optional extras, not requirements for the native Books request flow.

## 2. Secure Shelfmark proxy authentication

1. In Shelfmark **Settings → Security**, select **Proxy Authentication** with `Remote-User` as user header, `Remote-Groups` as admin group header, and `admins` as admin group name. The equivalent Shelfmark options are `AUTH_METHOD=proxy`, `PROXY_AUTH_USER_HEADER=Remote-User`, `PROXY_AUTH_ADMIN_GROUP_HEADER=Remote-Groups`, and `PROXY_AUTH_ADMIN_GROUP_NAME=admins`.
2. Restrict Shelfmark's API to the trusted Jellyfin host or private container network. These headers grant identity at Shelfmark; an untrusted caller able to send them could impersonate a user. If you separately publish a Shelfmark website, protect it with its own authenticated reverse proxy. Do not expose the proxy-auth API directly.
3. Confirm Jellyfin can reach Shelfmark at a **private base URL**. For containers sharing a network, `http://shelfmark:8084` is an example; use the service name and port that your deployment actually provides. No user browser needs direct access to this API.

Moonbase Books sets `Remote-User` from the validated Jellyfin username and sends `Remote-Groups: admins` only for a validated Jellyfin administrator. It does not trust client-supplied identity headers or forward client cookies or tokens to Shelfmark.

## 3. Replace the Jellyfin plugin

1. Record your existing Moonbase version and prepare a rollback copy of its plugin directory, configuration, and persistent data. Back up the Jellyfin configuration directory's `plugins/configurations/Moonfin.Server.xml` and `plugins/configurations/Moonfin/books-keys` if they exist. Preserve permissions and keep the keyring private. Do not erase other plugins or media.
2. In **Jellyfin Dashboard → Plugins → Repositories**, remove the **official Moonbase repository entry** before installing this fork. Keep unrelated repositories. The fork's package sets `autoUpdate: false`, but that alone does not remove the old catalog's upstream update offer. There is currently no Moonbase Books updater catalog.
3. Obtain the Jellyfin ZIP and `SHA256SUMS` from [Moonbase Books Preview 1](https://github.com/ZepiGit/Moonbase-Books/releases/tag/v2.3.1.100-books.1); compare the downloaded ZIP's SHA-256 with the published checksum. Use the release ZIP rather than the automatically generated GitHub source-code archive. `SOURCE_REVISIONS.txt` identifies the plugin and embedded web source commits.
4. Check Jellyfin's active sessions for **Now Playing** and wait for playback to finish. Stop Jellyfin cleanly. Move the old Moonbase plugin directory to your rollback location outside the active plugins directory. Extract the ZIP into one active plugin directory so `meta.json` and `Moonfin.Server.dll` are at its top level. Do not install this build beside official Moonbase: both have the same plugin GUID and assembly name. For Docker, the plugins directory is commonly under `/config/plugins/`; for native packages, use the path documented for that installation.
5. Start Jellyfin. In the dashboard, confirm **Moonbase Books** loads as the single Moonfin Server plugin. Check Jellyfin's plugin logs for load errors. Keep the backed-up configuration and keyring until setup and rollback checks pass.

## 4. Enable and check Books

1. Open **Jellyfin Dashboard → Plugins → Moonbase Books → Settings**. Leave **Settings Sync** enabled, enable **Books** (`BooksEnabled`), and set **Shelfmark URL** (`BooksShelfmarkUrl`) to the private URL from step 2. Enter only an `http://` or `https://` base URL without credentials, path, query, or fragment. Save.
2. Open the plugin-served web app at `https://your-jellyfin-server/Moonfin/Web/` or sign in with a matching Moonfin Books native client. Use the existing Jellyfin account. The Books entry appears when authenticated plugin `Ping` advertises `booksEnabled: true`; an official native Moonfin app continues its normal Moonbase features but does not contain this new tab.
3. Search once under **Books** and **Audiobooks**. Release search may return `202` while the app polls a job ID. Confirm that results come from your intended Prowlarr indexers. Verify a regular account sees only its own active/status items and an administrator receives the intended Shelfmark role.
4. Before queuing a real download, confirm the selected indexer, downloader, category, completed-download path, and final persistent import location. One supervised request should reach the downloader and then the intended Jellyfin library. A request starts a **server-side** job; it does not download to the user's device. Do not use another person's queue entry as a test.

The authenticated Books API is under `/Moonfin/Books/v1/` on the configured Jellyfin server. A `503` can indicate disabled Books or an invalid Shelfmark URL. If the tab is absent, check the fork client, Settings Sync, plugin version, and Ping capability before changing server storage.

## Update and rollback

Keep the Books data-protection keyring at `plugins/configurations/Moonfin/books-keys` in the Jellyfin configuration directory backed up and private. Losing it invalidates older release selections; users must search again. Preserve Shelfmark's own data and the import destination separately. Review Shelfmark API and authentication behavior before changing its version.

For rollback, wait for playback to finish, stop Jellyfin cleanly, move the fork's plugin directory out of the active plugins path, restore the backed-up single plugin directory and matching configuration, then restart and check normal client functions. Restore the previous repository policy only if you intend to resume upstream updates. Preserve Books keyring and media; never wipe storage or download queues as part of plugin rollback. The Books UI in native fork clients will be unavailable against an official Moonbase build, while their other supported server features can continue.
